# OKR 命令速查

> 绝大多数情况你不用记这些——直接跟助手说人话就行。这份是给想自己动手的人备的。

底层是 [`lark-cli`](https://www.npmjs.com/package/@larksuite/cli) 的 `okr` 模块。

> ⚠️ **版本**：本文参数按 **lark-cli 1.0.96** 的 `--help` 写（本机实测核对过的是 npm 全局安装的那份）。**换版本前先核对**：`python tools/okr_feishu.py check-cli` 会告诉你这台机器上脚本**实际**会用哪条路径、那条路径上是什么版本；再用 `lark-cli okr +patch --help` 这类实际帮助核对参数——不同版本的参数名会变。

## 先确认用的是哪个 lark-cli

本机可能装了多个 `lark-cli`（实测 npm 全局 1.0.96、`PATH` 上 1.0.97）。脚本查找顺序是 `OKR_LARK_CLI` 环境变量 → `PATH` → 固定候选路径，**`PATH` 优先**：

```bash
python tools/okr_feishu.py check-cli
```

纯本地只读探测，不联网、不碰飞书数据。要钉死用哪一条，设 `OKR_LARK_CLI` 指向可执行文件（指向不存在的路径会直接报错、不静默回退）。详见 [安全与凭据](05-安全与凭据.md)。

## 先搞清楚三个概念

- **身份（`--as`）**：`user` 是你本人，`bot` 是应用身份。读自己用 `user`，读别人可能要 `bot`。**写入、评论固定用 `user`。**
- **风险等级**：每个命令都有 `read` / `write` 标记，带 `--dry-run` 可以预演不执行。
- **目标定位的参数名不统一**：备注/正文用 `--target-id`；进展用 `--target-type` + `--target-id`；评论也用 `--target-type` + `--target-id`。老文档里的 `--id` / `--level` 在部分命令上已经不可用。

## 读

```bash
# 我是谁
lark-cli contact +get-user --as user

# 按姓名找人，拿到 open_id
lark-cli contact +search-user --query "张三" --as user

# 某人的周期列表
lark-cli okr +cycle-list --user-id ou_xxx --as user

# 某周期下的全部 O 与 KR
lark-cli okr +cycle-detail --cycle-id 7000000000000000001 --as user

# 看某条 O/KR 下我写过哪些进展
lark-cli okr +progress-list --target-type key_result --target-id 7000000000000000003 --as user

# 看某条 O/KR 下的评论
lark-cli okr +comment-list --target-type key_result --target-id 7000000000000000003 --as user

# 读单条 O / KR（改正文前拿「当前内容指纹」用；均为 read 风险级）
lark-cli okr objectives get --objective-id 7000000000000000002 --as user
lark-cli okr key_results get --key-result-id 7000000000000000003 --as user

# 可选的 OKR 分类
lark-cli okr categories list --owner-type user --page-size 100 --as user
```

## 写

⚠️ **所有写命令都建议先加 `--dry-run` 预演一遍**，确认请求体对了再真跑。预演通过不等于本人批准过，也不等于真实写入成功。

### 批量建一组 O + KR

`--input` 是一个 JSON 数组，每个元素一个 O，`krs` 是这个 O 下的 KR：

```bash
lark-cli okr +batch-create \
  --cycle-id 7000000000000000001 \
  --input '[
    {
      "text": "O 的正文",
      "notes": "计算公式、基线、验收人等口径信息",
      "category_id": "7001",
      "krs": [{"text": "KR1 正文"}, {"text": "KR2 正文"}]
    }
  ]' \
  --as user --dry-run
```

⚠️ `category_id` 必须是**字符串形式的正整数**（`"7001"`）；写成数字会被拒。分类由你本人逐个 O 确认，助手不代选。分类没定就不要提交。

### 给已有 O 补一条 KR

```bash
lark-cli okr +create --level key-result \
  --objective-id 7000000000000000002 \
  --content '{"text":"KR 正文"}' --as user --dry-run
```

### 改本人 O / KR 的正文

```bash
# 改 O
lark-cli okr +patch --level objective --target-id 7000000000000000002 \
  --content '{"text":"改后的 O 正文"}' --as user --dry-run

# 改 KR
lark-cli okr +patch --level key-result --target-id 7000000000000000003 \
  --content '{"text":"改后的 KR 正文"}' --as user --dry-run
```

保留原 ID，别用「新建一条一样的」代替修改。`+patch` 命令还带 `--score`、`--deadline`，**这两个本项目一律不用**。

⚠️ 改之前**先读当前内容**（`okr key_results get` / `okr objectives get`），把「原文 → 改后」摆出来确认；用封装脚本时，执行模式**必须**带上读到的当前内容指纹（见下），这样确认之后、落笔之前远端若被人改过会被拦下——不会盲目覆盖。

### 改 O 备注

```bash
lark-cli okr +patch --level objective \
  --target-id 7000000000000000002 \
  --notes '{"text":"备注内容"}' --as user --dry-run
```

⚠️ 备注只有 O 层有，KR 没有备注字段。这是飞书 OKR 的产品限制，不是脚本 bug。KR 要补口径信息，就写进 KR 正文，或者归到这个 O 的备注里。

### 写周进展

```bash
lark-cli okr +progress-create --target-type key_result \
  --target-id 7000000000000000003 \
  --content '{"text":"本周把灰度跑完了，错误率 0.2%"}' --as user --dry-run
```

- 用 `--target-type`（`objective` / `key_result`），**不是** `--level`；ID 用 `--target-id`，**不是** `--id`。
- 顺带记个百分比的话，`--progress-percent` 必须配 `--progress-status`（`normal` / `overdue` / `done`）：

```bash
lark-cli okr +progress-create --target-type key_result --target-id 7000000000000000003 \
  --content '{"text":"进展文字"}' --progress-percent 75 --progress-status normal --as user
```

### 评论

```bash
# 读评论
lark-cli okr +comment-list --target-type key_result --target-id 7000000000000000003 --as user

# 针对一条 O/KR 的全文发评论
lark-cli okr +comment-create --target-type objective --target-id 7000000000000000002 \
  --select-all --content '{"text":"评论内容"}' --as user

# 针对某段文字发选区评论
lark-cli okr +comment-create --target-type key_result --target-id 7000000000000000003 \
  --selected-text "被选中的原文" --content '{"text":"评论内容"}' --as user

# 回复已有评论串
lark-cli okr +comment-create --target-type key_result --target-id 7000000000000000003 \
  --ref-comment-id 12345 --content '{"text":"回复内容"}' --as user

# 周期评论（实体评论，不需要选区）
lark-cli okr +comment-create --target-type cycle --target-id 7000000000000000001 \
  --content '{"text":"评论内容"}' --as user
```

⚠️ 四条规矩：

1. 目标用 `--target-type` + `--target-id`（**不是** `--level` / `--id`）。KR 的枚举值底层是下划线 `key_result`；`tools/okr_feishu.py` 两种写法都接受。
2. **O/KR 的评论必须给 `--selected-text`、`--select-all`、`--ref-comment-id` 中的一个，且只能给一个**——一个都不给会被接口拒，多给也会被拒。
3. **周期与进展是实体评论，不需要选区**：只给 `--content` 即可，要回复再加 `--ref-comment-id`；**给了 `--selected-text` 或 `--select-all` 会被拒**。
4. 评论**只用 `--as user`**，且只给本人或你明确指定的对象发。

### 通知指定的人

```bash
lark-cli im +messages-send --user-id ou_xxx --text "消息内容" --as user --dry-run
```

- 默认一对一。发群要 `--chat-id`，属群发，本项目默认不做。
- 发送前核对**收件人、发送身份、完整正文**。消息里的 @ 提及不算收件人授权。
- 需要 IM 相关权限，跟 OKR 权限是两套（见 [权限清单](03-权限清单.md)）。

## 本仓库的封装脚本

`tools/okr_feishu.py` 把上面这些包了一层，好处有五个：**写操作默认只预演**、**写入固定用本人身份**、**预演会打印完整内容和内容指纹**、**改正文/备注执行前会做写前复核**、**报错给的是人话**。

```bash
python tools/okr_feishu.py whoami
python tools/okr_feishu.py find-user "张三"
python tools/okr_feishu.py cycles --user-id ou_xxx
python tools/okr_feishu.py okrs --cycle-id 7000000000000000001
python tools/okr_feishu.py categories
python tools/okr_feishu.py comment-list --target-type key-result --target-id 7003

# 读单条当前内容 + 指纹（改正文/备注前用；加 --dry-run 只回显请求）
python tools/okr_feishu.py get-content --level key-result --target-id 7003
python tools/okr_feishu.py get-content --level objective --target-id 7002 --field notes

# 写：先预演（不加 --execute 就是预演）
python tools/okr_feishu.py create --cycle-id 7000000000000000001 --input-file okr.json
python tools/okr_feishu.py update-content --level key-result --target-id 7003 --content "改后的 KR"
python tools/okr_feishu.py patch-notes --target-id 7002 --notes "口径说明"
python tools/okr_feishu.py progress --target-type key-result --target-id 7003 --content "本周进展"
python tools/okr_feishu.py comment-create --target-type objective --target-id 7002 --select-all --content "建议收敛表述"
python tools/okr_feishu.py notify --user-id ou_xxx --text "请查收"

# 你本人确认之后真写；改正文/备注必须带写前复核指纹
python tools/okr_feishu.py update-content --level key-result --target-id 7003 \
  --content "改后的 KR" --expect-current-fp 9ec17db282bf7146 --execute
```

> `--execute` 只表示「执行这条命令」，**不代表工具已经验证过你本人批准了**。确认这一关由助手按技能规则执行，脚本没有独立的真人门禁。
>
> 但有一道闸是真的：改正文/备注时缺 `--expect-current-fp` 就**拒绝执行**；带上以后，脚本会在落笔前重读远端比对指纹，对不上就中止。这防的是「你确认过之后、写入之前，别人又改了」——而不是防「你没确认」。确实读不到内容时用 `--no-current-check` 显式关闭，并如实说明这次没有远端变更保护。

`okr.json` 长这样（分类 ID 写字符串）：

```json
[
  {
    "text": "O 的正文",
    "notes": "计算公式、基线、验收人等口径信息",
    "category_id": "7001",
    "krs": [
      { "text": "KR1 正文" },
      { "text": "KR2 正文（进取型要写门槛目标）" }
    ]
  }
]
```

## 原始 API 通道

`lark-cli` 自带完整接口，命令不够用时直接打 HTTP 路径：

```bash
lark-cli api GET /open-apis/okr/v1/users/ou_xxx/okrs --params '{"user_id_type":"open_id","page_size":10}' --as bot
```

## 本项目**不做**的事

不管你怎么说，下面这些都不会被自动执行：

- 改 OKR **分数**（`--score`）——分数是绩效口径，助手不碰
- 改**权重、排序、对齐关系、截止日期**
- **删除**任何东西（O、KR、进展、评论）
- 修改**别人** OKR 的正文
- 未经你明确指定就给别人的 OKR 写评论，或把通知群发出去

前几条要你自己在系统里手动做，或者找你的 Leader。想给同事的 OKR 提意见，可以明确指定对象后让助手写评论——但只评论，不改对方的正文。
