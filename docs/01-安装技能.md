# 安装核心技能

核心包位置是本仓库的 `skills/product-rd-okr-writer/`，技能名称保留 `product-rd-okr-writer`。应复制或导入整个目录，不能只复制SKILL.md而漏掉references。

## 先了解目标工具的导入方式

不同AI工具的技能目录、发现方式和调用方式可能不同，按目标工具当前说明操作；本项目没有把未经实际安装的工具写成已兼容。不要把演示路径当成你机器上的真实安装位置。

1. 在目标工具支持的位置导入整个 `product-rd-okr-writer` 目录，保留相对结构。
2. 确认入口为 `product-rd-okr-writer/SKILL.md`，references下所有核心文件一起存在。部分资源按需读取，不要求每次加载全部内容。
3. 在工具内明确调用该技能，给一份脱敏写作或审核材料，检查实际加载的是这个候选而非旧版本。若工具不能自动发现技能，先按该工具支持的方式提供入口；这只能证明文档可读，不能据此宣称原生技能发现成功。
4. 分别记录安装、发现、引用加载与实际对话结果，写明工具版本和候选提交。包格式检查不代替这些实际步骤。

核心只使用文本与包内相对引用，不需要Python、飞书、Vault绝对路径或额外技能。开发用的静态检查程序不是运行依赖。包内[安装说明](../skills/product-rd-okr-writer/安装说明.md)可随整个技能目录携带。

## 安装后如何使用

直接说“帮我写OKR，这季度想做……”或“请审这份本人／成员稿，包括备注”。完整想法直接起草，部分想法补关键缺口；没有思路可以选择拆法或看示例。审核默认交付意见，不强制重写。

当前对话继续已有稿即可；新对话粘贴稿件与必要背景，不自动保存或恢复。示例均为虚构，目标值与分类不能自动带入真实稿。

本轮不会自动安装到用户全局技能目录、改用户配置或连接飞书。Codex、WorkBuddy、Claude Code等工具的安装、发现、加载和核心使用必须逐项留实际记录；本说明本身不代表任何宿主已通过。核心候选静态检查结果见该候选交付记录。
