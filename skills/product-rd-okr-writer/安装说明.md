# 安装说明

> 这份文件给你（使用 OKR 填写助手的人）看。
> **只想写 OKR 的话，读到第三节就够了**，飞书连接是可选项。

## 一、你需要先有什么

WorkBuddy 客户端（本机安装版）。没有的话先找你的 Leader 或 IT。

---

## 二、三步装好技能

### 第 1 步：找到 skills 目录

在文件资源管理器的地址栏粘贴下面这行，回车：

```text
%USERPROFILE%\.workbuddy\skills
```

如果提示路径不存在，先打开一次 WorkBuddy，再试一次。

### 第 2 步：把文件夹放进去

把收到的 **`product-rd-okr-writer` 整个文件夹**复制到上一步那个目录里。

放好之后应该是这样：

```text
C:\Users\你的用户名\.workbuddy\skills\product-rd-okr-writer\SKILL.md
```

⚠️ **最常见的错误是多套了一层**。如果变成下面这样，工具读不到：

```text
...\skills\product-rd-okr-writer\product-rd-okr-writer\SKILL.md
```

### 第 3 步：验证

打开 WorkBuddy，新建一个任务，输入：

```text
@skill://product-rd-okr-writer
```

能调起来就装好了。

**到这里已经可以正常使用了。**

---

## 三、怎么用

不用记命令，说人话就行：

- 「帮我写 Q4 的 OKR」
- 「上级给了我这几条 KR，帮我拆成我自己的 OKR」
- 「我想把 XX 这件事做成 OKR」

它会先问你 5 个问题（你负责什么、现在最痛的问题、希望带来什么变化、谁要配合、每个 O 打算怎么拆），然后给你 **3-5 个 O + 配套 KR**，最后附一份自查结果。产出文本可以直接粘进 OKR 系统。

**它会提醒你给每个 O 选分类，但不会替你选、也不会建议你选哪一类。** 这是你和 Leader 的事。

它不会做的事：不审核别人的 OKR、不评分、不碰绩效和奖金、不替你拍数字。

---

## 四、可选：连飞书（约 10 分钟）

连上之后多两个便利：

| | 没连 | 连了 |
| --- | --- | --- |
| 承接上级 OKR | 你截图 / 复制粘贴给它 | 它自己读你上级的 OKR |
| 交稿 | 你自己复制粘贴进系统 | 你确认后它帮你写进飞书 |

**不连完全不影响使用**，第三节那样用就行。

要连的话跟这个顺序走：

1. 确认装了 Node.js（`node --version`）
2. 装 lark-cli：`npm install -g @larksuite/cli`
3. 建一个飞书自建应用，拿到 App ID 和 App Secret
4. 给应用开通 OKR 相关权限（**只勾你要用的**，删除类权限别开）
5. **创建版本并发布**——⚠️ 这步最容易漏，不发布权限不生效
6. 配一下：`lark-cli config init --app-id <你的 App ID> --app-secret-stdin --brand feishu`
7. 授权：`lark-cli auth login --domain okr`
8. 验证：`lark-cli doctor`

完整图文步骤见 [`docs/02-连接飞书.md`](../../docs/02-连接飞书.md)，权限项清单见 [`docs/03-权限清单.md`](../../docs/03-权限清单.md)。

> 上面那 8 步已经写全了，照着做就行。如果你只是从仓库里单独抽出这个技能文件夹装的、没有整个仓库，那些文档不在你机器上——**不影响，上面步骤够用**。

配好之后跟助手说一声「**飞书连好了**」，它就会自己去读，不用你再粘。

⚠️ **安全提醒**：App Secret 只存在你自己的机器上，不要发给别人、不要写进任何代码或文档。详见 [安全与凭据](../../docs/05-安全与凭据.md)。

## 五、其他 AI 工具能不能用

技能本体就是**一个纯文本文件夹**（`SKILL.md` + `references/`），没有专有格式，理论上多数工具都能加载。

| 工具 | 目录 |
| --- | --- |
| WorkBuddy | `%USERPROFILE%\.workbuddy\skills\` |
| Codex | `%USERPROFILE%\.codex\skills\` |
| Claude Code | `%USERPROFILE%\.claude\skills\` |

各家的调用写法略有不同（WorkBuddy 是 `@skill://技能名`），放对目录后再按你那个工具的用法调。

> ⚠️ **如实说明**：**跨工具兼容性本项目只在目录结构层面适配过，没有逐家实测。** 上面三个目录也只是常见惯例，不保证是各家当前的最新规范；放进去调不起来是可能的。真要用别的工具，建议先问一下你那个工具的使用方式。

⚠️ 飞书读写那部分需要能执行本地命令（`lark-cli`）**和 Python 3**。工具不支持执行命令的话，飞书功能用不了，**填写功能不受影响**。
