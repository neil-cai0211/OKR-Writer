# 连接飞书

> 想让助手直接读你 Leader / 你自己的 OKR，并帮你把成稿写进飞书，就跟着这份走。
> **不连也能用**——把 Leader OKR 粘给助手，效果一样，只是要你自己复制粘贴。

整个过程大约 10 分钟，需要一个飞书账号，以及你所在企业允许自建应用（如果公司管得严，找 IT 帮忙）。

---

## 先想清楚：你要连到什么程度

| 需求 | 要不要连飞书 |
| --- | --- |
| 我只想让助手帮我把 OKR 写出来，自己复制粘贴 | **不用连**，装完技能就能用 |
| 我懒得把 Leader OKR 截图/复制过来，想让它自己读 | 要连，**只需读**的权限 |
| 我想让它把写好的 O/KR 直接写进我的飞书，或改我自己已有的条目 | 要连，**读 + 写**的权限 |
| 我还想让它给指定对象的 OKR 写评论、给指定的人发通知 | 要连，**读 + 写 + 评论**权限；通知另需 IM 权限 |

下面的步骤是「读 + 写」的全量配置。**只读的话：第 4 步只开读权限即可，但第 5 步「发布版本」仍然必须做**——不发布，权限不生效，只读也读不了。

---

## 第 1 步：确认装了 Node.js

打开终端（Windows 用 PowerShell 或 Git Bash，macOS 用终端），运行：

```bash
node --version
```

出现类似 `v20.x.x` 就没问题。官方 MCP 要求 Node 高于 v20；本项目的 `lark-cli` 也建议用 LTS 版本。

**如果提示找不到命令**：去 <https://nodejs.org> 下载 LTS 版本装上，再回来重试。

---

## 第 2 步：装 lark-cli

```bash
npm install -g @larksuite/cli
lark-cli --version
```

能打印版本号就成了。本项目按 **1.0.96** 核对过参数；你的版本不同也不一定有问题，但动手前建议先看 `lark-cli okr +patch --help` 确认参数名。

装完一般能直接敲 `lark-cli`。如果提示找不到命令，说明 npm 的全局 bin 目录不在 PATH 里，问一下 AI 助手或者搜一下「npm 全局路径 加 PATH」，把那个目录加进环境变量即可。

---

## 第 3 步：建一个飞书应用，拿 app_id 和 app_secret

### 路线 A：一键注册（AI 助手能帮你跑，**本项目未实测这条路线**）

```bash
lark-cli config init --new
```

这条命令会打开浏览器，你按提示走完就能拿到一个应用，配置自动写好。

> ⚠️ 两点如实提醒：
> 1. 这个命令会**阻塞等待**你在浏览器里完成操作。如果在 AI 助手里跑，它可能一直卡着——可以让它用后台方式跑，把浏览器链接发给你，你点完再继续。
> 2. **本项目没有实测过这条路线**，只确认命令存在。如果卡住，直接改走下面的路线 B。

### 路线 B：手工在开放平台建（本项目采用的心智模型）

1. 打开 <https://open.feishu.cn/app> → 创建应用 → **自建应用**
2. 记下 **App ID** 和 **App Secret**（App Secret 只显示一次，存好）
3. 接着往下走第 4 步开通权限

拿到之后配置一下：

```bash
lark-cli config init --app-id <你的 App ID> --app-secret-stdin --brand feishu
```

执行到 `App Secret` 提示时，粘贴 secret 然后回车。用 `--app-secret-stdin` 是为了避免密钥出现在命令行历史里，比直接写参数安全。

配置存在 `~/.lark-cli/config.json`，**secret 存在系统钥匙串里**，不在这个文件里。但这个 `config.json` 仍然不要提交到任何 Git 仓库（见 [安全与凭据](05-安全与凭据.md)）。

---

## 第 4 步：开通权限

在应用后台的**权限管理**里开通下列权限项（名称照抄，代码见 [权限清单](03-权限清单.md)）：

**读：**

- 查看 OKR 周期、目标与关键结果
- 查看 OKR 进展记录
- 查看 OKR 分类
- 通讯录基础信息（用于按姓名找人）

**写：**

- 编辑 OKR 目标与关键结果
- 写入 OKR 进展记录

**评论（要给指定对象评论才需要）：**

- 读 OKR 评论
- 写 OKR 评论

**通知（要给指定的人发消息才需要）：**

- 发消息（IM）相关权限——**和 OKR 权限是两套**，不要以为开了 OKR 权限就能发消息

> **只读场景**：只开那几条读权限就够，`writeonly` / `delete` 全都别开。
>
> ⚠️ 权限是**按租户**生效的：你这边开出来了，不代表所有企业租户都能用；换公司环境要重新开。

---

## 第 5 步：发布版本

应用的版本需要**发布**后权限才生效（企业自建应用一般需要管理员审批）。

在应用后台 → 版本管理与发布 → 创建版本 → 填个版本号（比如 `1.0.0`）→ 发布。如果提示要管理员审核，等一下或者找 IT。

⚠️ **没发布就用会报权限不足**，这是最常见的卡点。**只读也要发布。**

---

## 第 6 步：授权登录

```bash
lark-cli auth login --domain okr
```

会给你一个验证链接（或二维码），用飞书扫码授权。

> 只想要 OKR 权限就用 `--domain okr`，不要用 `--domain all`——那会申请一大堆用不上的权限。

如果它阻塞了，在 AI 助手里可以让它改用两步走：

```bash
lark-cli auth login --domain okr --no-wait --json   # 先拿到链接
lark-cli auth login --device-code <刚才返回的码>     # 授权完再收尾
```

---

## 第 7 步：验证

```bash
lark-cli doctor          # 体检：配置、授权、网络
lark-cli auth status     # 看当前授权状态
```

然后拿本仓库的封装脚本试一下：

```bash
python tools/okr_feishu.py whoami
```

- 需要本机有 **Python 3**（`.py` 脚本，零第三方依赖）。
- **在仓库根目录执行**：脚本里用的是 `tools/...` 这种相对路径，换目录会找不到文件。
- 如果你的网络环境需要代理，脚本默认**保留**你系统里的代理设置；只有明确用 `--no-proxy` 才会绕过代理。

能打印出你自己的信息，说明**通讯录身份调用**通了。

> ⚠️ **别把这一步当成"全链路通过"**：`whoami` 成功只证明通讯录接口可用，**不代表**能读 Leader 的 OKR、能读分类、或者能写入。要逐项试。

---

## 第 8 步：告诉助手

跟助手说一句「**飞书连好了**」，它就会按需去读，不用你再手动粘 Leader OKR。

如果没连，它会自动走原来的老路——问你 Leader OKR 是什么。**不需要告诉它你连没连**，它会自己判断。

---

## 配完之后

- 读 Leader OKR：直接说「读一下我 Leader 的 OKR」
- 写进飞书：先让它出完整成稿 → 你核对 → 说「写」
- 改自己的条目：说清是哪一条 → 它展示「原文 → 改后」→ 你确认 → 才改
- 评论 / 通知：说清**对象是谁**，它展示完整内容 → 你确认 → 才发

完整规矩见技能里的 [飞书读写](../skills/product-rd-okr-writer/references/feishu-integration.md)。

## 相关官方方案（外部链接 · 本项目未验证）

> 这一节只是**指路**，不是本项目的安装步骤。本项目没有实测过这条路，也不把它作为推荐路线。

飞书开放平台自己提供了一套 **OpenAPI MCP**（npm 包 `@larksuiteoapi/lark-mcp`），让支持 MCP 的 AI 工具通过 MCP 协议直连飞书，覆盖多维表格、云文档、消息等一批能力。官方文档：

- 本地安装与使用：<https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/mcp_integration/mcp_installation>
- 高级配置（令牌模式、工具语言、工具名格式等）：<https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/mcp_integration/advanced-configuration>

如实提醒几点：

- 官方 MCP **默认只启用一部分 OpenAPI**，其余的要在配置里手工指定开启；**OKR 相关接口不在默认启用列表里**。
- 官方对**非预设接口注明未做兼容性测试**，实际效果不保证。
- 它和本项目的 `lark-cli` 路线是**两条不同的路，不互相替代**：本项目按 OKR 场景做了取数、默认预演、本人确认和范围边界；官方 MCP 是通用通道，OKR 的安全边界要你自己另外补。
- 走 MCP 一样要自建应用和授权，凭据同样只放在你自己机器上。
- 本节的链接和事实来自官方文档，**本项目未在其上跑过任何真实调用**。
