# 核心验证范围

`check_package.py`只用Python标准库检查核心Markdown的UTF-8、代码围栏、相对链接目标、包内引用不外逃和资源可达性。不联网、不运行飞书、不证明AI对话效果。运行方式：

```text
python tests/core/check_package.py
```

技能格式另用skill-creator提供的quick_validate检查。Python只是开发检查工具，不是技能运行依赖。

## 行为覆盖计划（尚非执行记录）

下面是供开发自查、实际试用另选输入的边界清单；没有实际原始回复前均为未验证。不要把此表的预期注入独立试用者，不能用规则复述或编写理想对话代替运行。

| 组 | 需要给的输入 | 观察实际行为 |
| --- | --- | --- |
| A1 | 从问题出发，责任和成果完整，分类已定 | 直接给有质量的O/KR及备注；不重问已知信息、不强制选拆法 |
| A2 | 从季度计划出发，有主线但尚未定结果 | 先用已有信息展示部分稿，只补关键缺口；不要求先编痛点 |
| A3 | 有具体事情但无拆解思路，分别请求看一种、三种示例 | 同一件事简短比较；选择、调整后围绕一稿，不循环重选 |
| B1 | 上级相关O/KR、本人边界与充分结果要求 | 形成个人贡献，解释支撑，不照搬团队承诺或新增职责 |
| B2 | 只有上级相关材料，没有本人负责部分 | 优先问个人责任，不索取上级整份；不自行分派工作 |
| C1 | 同一结果分别放KR正文、可对应备注；另放无对应备注 | 前两种判断一致；第三种不跨KR借用，说明实际缺口 |
| C2 | 行动加有用交付物；成果明确但少验收细节；只有动作进度 | 区分合理里程碑、黄色建议和成果缺失红色，不凭关键词 |
| C3 | 三类目标；进取型逐条数值/定性门槛、空标题、不同称呼 | 每类明确目标；仅进取型额外要求逐条可判断门槛 |
| C4 | 下降指标目标与较大门槛数值；上升指标相反；方向矛盾 | 理解最低可接受语义，不机械要求门槛更小；冲突说明依据 |
| D1 | 已知整份1、6个O；仅展示1个O；已知O分别1、5条KR；KR不全 | 整份O偏少或多提醒，局部不推断；KR1红、超过4黄，缺全量不下数量结论 |
| D2 | O量化目标、KR明细、上级KR直接作O；O含产品版本数字 | 按实际目标/明细判断，不把任意数字字符当量化目标 |
| D3 | 已知周期与KR冲突；周期未给；内容超过字数提醒线 | 冲突有证据才红；未知待确认；字数只是建议 |
| E1 | 本人同O及跨O一致KR，空白标点或明确@提及不同 | 比较副本归一化，原文保留，指出双方位置，不推断动机 |
| E2 | 正式承接单条KR一致；完整O+全部KR一致；只有O一致 | 前两种红且整改在下级；仅O一致不单独报重复 |
| E3 | 正式承接大部分雷同；KR条数不同但实质不同；只有近义 | 橙色给三项依据且交当前Leader；不因条数不同自动橙，不把语义近当文本一致 |
| E4 | 明确同级单条/完整/雷同；关系未知；仅有系统对齐 | 同级相同雷同均不报，未知不冒充豁免/通过，对齐不自动等于承接 |
| F1 | 自审有问题稿、完整合格稿，Leader单人和多人稿 | 成员→O→全部KR及备注→集中意见；有依据和具体改法；默认意见即交付，无问题如实肯定 |
| F2 | 材料未提供、无权限字段、来源明确未填写 | 保留三者区别，不猜测成员未填写或补造备注 |
| G1 | 用户拒绝候选、纠正责任、审核后明确要求改稿 | 更新正文及备注，沿用已知内容，不重采访或暗改目标值/分类 |
| G2 | 同一生成稿和同一备注再进入审核 | 同规则一致，不以阶段稿代替充分输入下的完整交付 |
| H1 | 脱敏飞书材料（仅本地文本），字段和分页完整性标缺 | 按共同约定保留归属/缺口，不声称真实读取或联调通过 |

实际验证应记录候选提交、实际加载技能、工具与版本、原始输入、补充、回复、判定依据、失败与复验。核心功能、宿主兼容、飞书读取/联调、Neil本人试用分项报告，任何未测必测行为都不能宣布核心整体验收完成。
