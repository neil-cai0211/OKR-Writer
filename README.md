# OKR审核与改进

一个专注于OKR审核的Skill：判断O、KR及对应备注的质量，检查已确认的组织要求，给出有依据、可采用的改进建议。

核心知识只有一套：好的O与KR、备注怎么用、类型怎样理解与选择，以及本项目的硬性要求和判断边界。AI可以复用这些知识帮你起草或修改，不另外规定写作访谈、固定问答轮数或必填表。

## 怎么使用

把原稿与对应备注交给助手，例如：

- “审核我的这份OKR，指出必须调整和建议调整，并说明怎么改。”
- “按成员审核这些OKR，先看每个O及全部KR，再集中给意见。”
- “解释这几类目标的区别，帮助我理解该怎样选择。”
- “按同一套标准帮我起草或修改一版，未知值标明待补。”

审核联合阅读O、全部KR及对应备注；明确问题要有依据，信息不足说明缺口，合格内容如实认可。默认交付意见，用户要求再给修改稿，不打分、排名或推测动机。

## 安装和边界

按[安装说明](docs/01-安装技能.md)导入完整技能目录。为保持已有引用，项目与技能标识仍保留OKR-Writer、product-rd-okr-writer；产品能力已收敛为审核与改进。

本Skill只使用文本与相对引用，不依赖Python、飞书或本机知识库。外部工具可取得材料后交给它，但本项目不实现连接、授权、取数、写回或通知；这些动作也不是审核请求的默认授权。

开发格式检查见[检查说明](tests/core/README.md)。包检查、实际内容试用、宿主安装发现和真实人员体验分别报告，不从某一项通过推断其他项。旧写作流程、模板、飞书程序及说明已从当前交付移出，历史在Git提交及项目工作区快照中保留。
