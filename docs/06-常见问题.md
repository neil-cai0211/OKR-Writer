# 常见问题

## 安装相关

### 装完提示找不到 `lark-cli` 命令

npm 的全局 bin 目录不在 PATH 里。

```bash
npm prefix -g        # 看全局目录在哪
```

把它下面的那个 bin 目录（比如 Windows 的 `%APPDATA%\npm`，macOS 的 `/usr/local/bin`）加进系统 PATH，然后重开终端。

### `node --version` 提示不是内部或外部命令

Node.js 没装。去 <https://nodejs.org> 装 LTS 版本。

### 技能装了但调不起来

大概率是**目录多套了一层**。正确长这样：

```text
...\skills\product-rd-okr-writer\SKILL.md
```

如果变成 `...\skills\product-rd-okr-writer\product-rd-okr-writer\SKILL.md`，工具读不到。

## 飞书连接相关

### 提示权限不足 / 无权限

九成是**权限改了没重新发版**。权限改动必须走「创建版本 → 发布」，等审批通过才生效。

第二步：确认权限项真的勾上了，见 [权限清单](03-权限清单.md)。

### 读自己的 OKR 失败，但读别人的成功

身份问题。试试换：

```bash
lark-cli okr +cycle-list --user-id ou_xxx --as bot
```

### 读别人 OKR 报权限不足

用 `--as user` 读别人是需要额外授权的。先确认：

- 是不是用了 `--as user` 去读别人 → 改成 `--as bot`
- 或者是不是压根没给对方可读的权限（飞书 OKR 本身有可见性设置）

### `auth login` 卡住不动

它在等你完成浏览器授权。如果你在 AI 助手（AI Agent）环境里跑，它会一直阻塞。用两步走：

```bash
lark-cli auth login --domain okr --no-wait --json   # 拿链接，先返回
lark-cli auth login --device-code <返回的码>        # 授权完再收尾
```

`--device-code` 那一步**在用户点完授权之后**再跑。

### 授权时申请了一堆用不上的权限

用了 `--domain all` 或者 `--recommend`。换成精确的：

```bash
lark-cli auth login --domain okr
```

已经授权过的话，先 `lark-cli auth logout` 再重来。

### 公司不让建自建应用

那就先不连飞书——技能本体的填写功能完全不依赖飞书，手动粘贴上级 OKR 就行。

要申请的话找 IT，一般会批，只是要说明用途。

### 网络超时 / 命令卡住

有些网络环境需要走代理。`lark-cli` 会读系统的 `http_proxy` / `https_proxy` 环境变量。如果设了但不通，就临时清掉：

```bash
unset http_proxy https_proxy all_proxy
lark-cli doctor
```

`tools/okr_feishu.py` **默认保留**你系统的代理设置（企业网络通常需要它）；只有代理反而导致连不上时，才用 `--no-proxy` 显式绕过：

```bash
python tools/okr_feishu.py whoami --no-proxy
```

## 写 OKR 相关

### 建 O 时报 `invalid parameters`，提示要分类

说明你们企业强制要求给 O 填分类。先查有哪些分类：

```bash
lark-cli okr categories list --params '{"owner_type":"user","page_size":100}' --as user
```

然后**自己选一个**告诉助手。助手不会替你选分类——这是公司口径里明确要求本人定的事。

### KR 没法写备注

飞书 OKR 的产品限制：**只有 O 有备注，KR 没有**。KR 要补口径信息，就写进 KR 正文，或者归到这个 O 的备注里。

### 助手给我选了 OKR 分类

这不对。分类（承诺型 / 进取型 / 挑战型）**只能你自己定**，助手只应该提醒你别忘了选。看到它代选，直接指出来。

### 改 KR 正文时提示「必须先做写前复核」

改本人已有的正文/备注，脚本要求你**先读当前内容**、拿到指纹，执行时再带上：

```bash
python tools/okr_feishu.py get-content --level key-result --target-id 7003
python tools/okr_feishu.py update-content --level key-result --target-id 7003 \
  --content "改后的 KR" --expect-current-fp <上一步给出的指纹> --execute
```

这不是找麻烦，是防止「你确认完、还没写进去的这段时间里，别人又改了同一条」——不加指纹就被覆盖了。确实读不到内容（比如没有读权限）才用 `--no-current-check` 关掉，关掉时助手应当如实告诉你这次没有远端变更保护。

### 提示「远端内容已变化，已中止」

好事，说明闸起作用了：你确认时的版本已经被改过，所以脚本没写。这时请助手**重新读一次**，把新的「原文 → 改后」再摆给你看，你确认后重新生成一次操作。之前那次确认已经作废。

### 进取型的 KR 它说不用写门槛目标

不对。**进取型 O 里的每一条 KR 都必须有门槛目标**，而且门槛要能判断（数值或明确的里程碑）。说「表现良好」这种不算。

这条没有例外。

## 关于怎么和它聊

### 它一上来就甩给我一张表要填

不应该。**新版不要求先填问卷**——它按你已经说的内容判断从哪进，每轮只问**当前最影响继续的那一个**问题。

你仍然看到一大串问题，有几种可能：

- 你明确说了「一次给我全部问题」（这时它会照给）
- 你给的内容太少，它只能从最基础的问起——**这正常**，但它应该**一次只问一项**
- 版本较旧——更新说明见 [安装技能](01-安装技能.md)

### 它问的这个问题里塞了好几个要求

比如「请说明你的职责范围、期望变化、协作方和拆解方式」——这是**一条问题里塞了四份作业**，不符合现在的要求。

正确做法是**拆开，一次一项**。看到这种可以直接指出来。

### 它非要我先选「策略/维度/里程碑」才肯给我东西

不需要。**拆解方式在具体目标里讨论**，不是开场必答题。

有了目标之后它可以建议一种拆法并举个例子，你确认或换一个才落成正式 KR。未确认前只会标「拆法待确认」，不会默默替你定。

### 我说「你先出一版」，它反问一堆

如果**你已经说清主线和自己的责任**，它应该直接给草稿，未知的地方标「待确认」。

只有当你**只给了岗位、还没说想推动什么**时，它才该先问一个方向问题——**这是对的**，因为工作重点只能你定，它不能替你编。

### 我拒绝了它推荐的拆法，它又绕回来推

不对。**你拒绝推荐，它就按你已确认的方式继续**，不回到被拒绝的那个推荐，也不改推另一个。

看到它反复推同一个，直接指出来。

### 它是不是一定要我把数字都填齐

不用。**不知道的标「待确认」，它不会替你拍数字。**

阶段草稿里留「待确认」是正常的——**但那份草稿也不会被标成可以直接定稿**。

### 它一直催我填分类

草稿阶段允许标「分类待本人确认」。**定稿前补齐就行**，不必每轮都问你一遍。

**分类只能你自己定**——它不代选、不建议，这条始终不变。

## 关于内容质量

### 它说我这条 KR「支撑不住 O」

它会写清三段：**具体位置和原文依据 → 对价值／支撑／验收有什么影响 → 可怎么改**。如果只写「支撑不足」四个字，你可以要求它说清是哪条 KR、对应不上哪部分。

⚠️ **支撑不足是质量建议，不是新的红线**——它**不判不合格**，只在建议层提醒并给你选择。它**不会**自造替代工作，**也不会**替你编一个满意度数值。

如果你确实判断不出（比如背景信息不够），它应该标「待确认」，**不能硬下因果结论**。

### 它说我这条 KR 没有业务价值

先看它说的是不是财务指标。**业务价值不等于收入利润**——客户体验、可靠性、研发效率、风险降低、有用的探索结论**都算价值**。

**阶段成果和合理的定性验收也能体现价值，不能因为没有财务指标就判问题。** 它如果用「没有收入/利润数字」来判你有问题，这个理由不成立，可以指出来。

### 它说我的里程碑 KR「不够量化」

判据应该是**「能不能回答做到什么程度算完成」**，**不是「有没有数字」**。

- 有明确成果 + 覆盖范围 + 可查的成功状态 → **合理的里程碑成果，如实认可**
- 只有交付物或方向、没有任何达成表述 → 在 🟡 建议层提醒补

**只有命中硬性判据（纯动作、活动量当成果、进度跟踪）才判不合格。** 它如果因为「看起来像任务」就否掉你的里程碑 KR，违反现有口径。

### 它把我的数值目标改小了 / 帮我把数字填上了

不对。**数字必须由你提供或确认**。它可以建议，但必须标成「AI 建议」并等你确认。

**目标值可以因资料不同而变化**——但两边判断不一致时，它应说明差在哪，而不是默默改掉你的意思。

### 我只想承接上级一条 KR，凑不满 3-5 个 O

这是真实存在的场景（岗位窄、职责集中）。**3-5 个 O 是建议值，不是硬指标**，不会只因为数量就判你不合格。

- 确实只有一件事值得做成 O → 就写 1 个 O，在备注里写明覆盖范围
- 只是没想全 → 找找支撑、协作、改进类的其他 O

**别为了凑数硬拆**。

### 它说我的 KR「只写了动作」

检查这条 KR 里有没有：**谁**、因为**什么**变化、变成了**多少**。三样都没有的话，它说得对。

### 它说我的 KR 跟同事写得一样，算重复吗

**先看关系，再看内容。** 有没有正式上下级承接关系，决定了这件事报不报；**同级之间一律不报**。

比较的单位是**某一条完整 OKR**，也就是**一个 O 加上该 O 下全部 KR**。

**上下级承接关系**下会判 🔴 的：

- 你承接的 KR 和正式承接的上级那条完全一致（整改在你这边，上级不计入问题点）
- 你和上级的**某一条完整 OKR（O + 全部 KR）完全一致** → 会列出双方 O 及全部 KR 的对应原文

**和任何人**都会判 🔴 的（不需要关系判断）：

- 你自己**同一个 O 底下**两条 KR 完全一致
- 你自己**跨不同 O** 的 KR 完全一致

只🟠 提醒、交 Leader 判断的：

- **上下级**之间某一条完整 OKR**大部分雷同但不完全一致** → 提醒、写清相同部分/关键差异/关注理由，**不直接判不合格**

**不判、不建议、不点名的**：

- **同级（无正式承接关系）之间的一切重复**：单条 KR 一致、整条完整 OKR 完全一致、大部分雷同、KR 条数不一致——**四类全不报**。同一件事被上级同时派发给多人时，同级写出相同内容是自然结果，点名会误伤承接方
- **单条 O 与他人一致**（含上级、同级）

**⚠️ 说不清就不算通过**：

- 对方是上级还是同级**说不清**，或者**拿不到对方全部 KR** → 标「**待确认**」，如实说这一项没查成、写清缺什么。**既不判成问题，也不按同级豁免填「通过」**。

**不设相似度分数、KR 比例或 O 数量门槛**，也不用「相同 O ≥2 个且占双方 O 数 ≥2/3」这类旧算法。只有语义相近不算文本完全一致。

### 进取型的门槛是不是一定要比目标值小

不一定。门槛是「**最低可接受结果**」。

- 指标越高越好（达成率、覆盖率）→ 门槛通常小于目标值
- 指标越低越好（响应时间、崩溃率、缺陷数）→ 门槛数值会**比目标值大**

别按「门槛一定比目标值小」去套。

### 我想让它检查我已有的 OKR

直接说「帮我看看我这份 OKR 写得对不对」，把稿子粘给它；连了飞书也可以让它读你指定周期的正式内容。**不用先走一遍填写问答**——已有稿就是完整输入。

它会逐个 O **保留你的原文和全部 KR 原文**，再给问题、依据和修改建议。符合标准的会如实说「暂未发现明显问题」并说明已具备的价值或支撑，**不会为了显得严格硬挑错**。

它会把三类分开：**硬问题**（🔴 进问题点）、**软建议**（🟠／🟡 只提醒、不判不合格）、**资料缺口**（标「待确认」，**既不判通过也不判不合格**）。

> ⚠️ **缺口多于 3 项也会全部保留。** 它可以先突出最影响质量的少数点作为当前展示重点，但**不能把其余未确认事项删掉或登记成通过**。

你只说检查时，它**只给建议，不会动你系统里的东西**。

### 想让它给同事的 OKR 写评论，或者给某人发通知

可以，但要满足两个条件：

1. **你必须明确指定对象**（哪个人的哪条 O/KR、通知发给谁）。没说清对象，它不会发。
2. **发之前它会把完整内容摆给你看**，你确认之后才发。

它不会自动评论、不会批量评论、不会群发通知，也**不会修改对方 OKR 的正文**。给同事提意见和「替对方审核」是两回事。

### 它说「已连接」但读不到 Leader 的 OKR

`whoami` 能跑通只说明通讯录接口通了，**不代表**读 Leader、读分类、写入都通。逐项排查：

- 周期选对了吗
- 读他人的权限或可见性设置够吗（有时需要换 `--as bot`）
- Leader 的姓名有歧义吗（同名的人不能猜）
- 都不行 → 让它直接告诉你读不到，你手动把 Leader 的 OKR 粘过去，效果一样
