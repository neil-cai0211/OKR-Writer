# OKR 写作与审核助手

把自己的问题、季度计划或上级相关目标整理成O、KR及对应备注，也能自审或帮助Leader审核单人、多人已有稿。工作重点、责任、分类和目标值由本人决定；AI主动梳理、给有依据的候选并帮助完善。

本轮是按已确认PRD重做的**核心候选**。核心可独立用粘贴材料，不依赖飞书、Python或本机知识库。核心静态包检查、实际对话验证、宿主兼容和Neil本人试用是不同结果，不能相互替代；当前验证以本轮交付记录为准，未提供实际记录的项目均未验证。旧v7说明和预演结果不作为本轮通过证据。

## 怎样开始

- 写作：“帮我写OKR，这季度准备做……，我目前的想法是……”
- 承接：“这是上级相关O/KR，我负责……，帮我形成自己的OKR。”
- 自审：“帮我审这份稿，包括下面这些对应备注。”
- Leader审核：“按成员和O审核这些稿件，给必须调整和建议调整即可。”
- 续写：在当前对话继续；换对话时粘贴已有稿与必要背景，不自动跨会话保存。

已有充分想法直接成稿；部分想法先用已有内容，只补关键缺口；没有拆解思路可直接选策略、维度、里程碑，或先看一种、三种简短示例，再围绕一份稿件完善。不会要求每个人先选拆法或一次填写长表。

写作交付O、KR及对应备注，分类或关键事实未明就保留阶段稿。审核默认交付意见，按成员→O→全部KR及备注→集中意见组织，明确要求再改稿；没有问题如实认可。

## 规则与质量

运行时判据只在[统一判据](skills/product-rd-okr-writer/references/okr-writing-rules.md)维护。它来自本项目已确认的公司口径，并非所有公司的通用制度。

[质量方法](skills/product-rd-okr-writer/references/quality-standards.md)用于实际完善价值、责任、支撑、结果验收和表达。正文与对应备注共同判断，合理行动加交付物可以作里程碑；不能把验收细节不足一律判红，也不能把没有实际成果一律降为建议。不做评分、排名、奖金换算或动机推断。

示例数字和职责都为虚构，不能成为真实用户默认值。数量提醒不是配额，不编造工作补数。

## 飞书是可选只读材料来源

只有明确请求读取时才进入连接流程；本轮范围为本人、指定上级、Leader明确指定且账号可见的组员，不自动遍历部门。人员、周期和权限需当次明确；取不到字段不等于未填写。读取后按[共同材料约定](skills/product-rd-okr-writer/references/material-input.md)交给核心，失败可粘贴材料继续。

飞书功能由另一开发线维护，真实读取和联调尚需独立验证。入口可查看[连接说明](docs/02-连接飞书.md)和[专属引用](skills/product-rd-okr-writer/references/feishu-integration.md)；这些文件可能仍含历史写入、评论、通知说明，本轮只读授权不包含这些动作，也不因旧脚本存在就认为已完成或可执行。核心候选不安装、不登录、不调用真实飞书。
