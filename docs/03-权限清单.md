# 权限清单

在飞书应用后台开通权限时，名称照着下表勾选即可。

## 读权限（查周期、查 O/KR）

| 权限名称 | 权限标识 | 什么时候用 |
| --- | --- | --- |
| 获取用户 OKR 周期 | `okr:okr.period:readonly` | 找「2026 Q4」这类周期的 ID |
| 获取 OKR 内容 | `okr:okr.content:readonly` | 读某个周期下的 O 和 KR 正文 |
| 获取 OKR 进展记录 | `okr:okr.progress:readonly` | 看你之前写过哪些进展 |
| 获取 OKR 分类 | `okr:okr.setting:read` | 查组织里承诺型/进取型/挑战型的分类 ID |
| 获取通讯录基础信息 | `contact:contact.base:readonly` | 按姓名把上级换成 open_id |

## 写权限（建 O/KR、写进展、写备注）

| 权限名称 | 权限标识 | 什么时候用 |
| --- | --- | --- |
| 编辑 OKR 内容 | `okr:okr.content:writeonly` | 新建 O / KR、改 O / KR 正文 |
| 写入 OKR 进展 | `okr:okr.progress:writeonly` | 写每周进展文字 |
| 删除 OKR 进展 | `okr:okr.progress:delete` | **不建议开**，本项目不会删你的东西 |
| 上传进展图片 | `okr:okr.progress.file:upload` | 只有你要在进展里插图才需要 |
| 读 OKR 评论 | `okr:okr.comment.readonly` | 看本人、或**明确指定对象**的 OKR 下的评论 |
| 写 OKR 评论 | `okr:okr.comment.writeonly` | 给本人或**明确指定**的对象写评论、回复评论串。不做未经指定的批量评论 |
| 删除 OKR 评论 | `okr:okr.comment.delete` | **不建议开** |

## 关于「分类」权限

分类（承诺型 / 进取型 / 挑战型）挂在 O 上。如果你的企业强制要求填分类，建 O 时要带上分类 ID。

```bash
lark-cli okr categories list --params '{"owner_type":"user","page_size":100}' --as user
```

⚠️ **分类由你自己选，助手不会代选**。查出来只是给你看有哪些选项，选哪个是你的决定。

## 最小权限建议

| 你要做的事 | 需要开 |
| --- | --- |
| 只读，不写入 | 读权限那几条就够了 |
| 读 + 写自己的 O/KR 和进展 | 读权限 + `content:writeonly` + `progress:writeonly` |
| 还要给指定对象写评论 | 再加 `okr.comment.readonly` / `okr.comment.writeonly` |
| 还要给指定的人发通知 | 再加 **IM 发消息**相关权限（和 OKR 权限是两套，不通用） |

三条 `delete` 权限本项目用不到，**别开**。

## 通知需要的权限（IM）

给指定的人发通知走的是**消息接口**，不是 OKR 接口：

- 需要为应用开通**机器人能力**，并开通发消息相关权限。
- 发送身份要在实际授权范围内选（`--as user` 或 `--as bot`），具体能发什么以你的租户实际配置为准。
- **不要**因为「OKR 权限开好了」就以为能发消息；也不要因为「能发消息」就以为能读 OKR。两套授权各自独立。

## 权限相关的坑

- **权限改了要重新发版才生效**。改完权限点「创建版本 → 发布」，等审批通过。
- **只读权限读不了别人的 OKR**。读自己的用 `--as user`，读上级的可能要 `--as bot`。
- **`offline_access`（离线访问）通常在授权时自动带上**，不用手动勾。
